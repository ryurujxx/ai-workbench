# 상태 양식

읽기 전용 양식이다. 프로젝트 지정 경로를 우선하고, 없으면 작업공간 안에 기록 위치를 한 번 정한다. 동명 파일을 먼저 확인하고 STATUS에 문서별 실제 경로를 명시한다. 아래 가상 예시를 실제 작업 이력으로 사용하지 않는다.

## 빈 양식

- 상태 개정·갱신 시각/순서·확인 출처:
- 프로젝트 작업공간:
- 참고 폴더·START 접근: 읽기 가능/불가/미확인, 확인 방법
- 정본 STATUS 경로:
- 문서별 정본 경로·접근 상태: REQUIREMENTS / DECISIONS / VERIFICATION / MVP_REPORT
- 역할별 세션·권한·전용 파일: 아래 소유권 표
- 총 제한시간·현재 시각 출처·종료 시각·남은 시간:
- 시간 예산: 기획 / 구현 / 검증 / 최종 통합·제출 예약
- 필수 산출물·제출 위치·제출 상태:
- 공개 평가 항목·배점·서술형 질문 위치:
- 현재 목표와 합의 범위:
- 요구사항 현황: 아래 진행 표
- 완료 작업과 근거:
- 진행 작업:
- 막힌 문제와 마지막 실제 오류:
- 미확인·사용자 결정:
- 다음 한 행동:
- 관련 파일·마지막 성공 실행/검증 명령·커밋:
- 실행 중 서비스·포트·재시작 방법:
- 외부 자료: 원본·확인 버전/날짜·실제 경로·적용 범위·등록 상태
- 사용자 직접 확인 항목과 결과 출처:
- 마지막 근거 누적 시점: DECISIONS / VERIFICATION / MVP_REPORT
- 중단·재개 최소 정보 확인: 최신 버전·소유권·마지막 성공 상태·다음 행동

### 역할·파일 소유권

| 역할/세션 | 프로젝트 접근 | 쓰기 허용 범위 | 전용 인계 파일 | 마지막 확인 |
|---|---|---|---|---|
| 기획 | 읽기 | 기본 없음 | 승인 시 PLANNING_HANDOFF | [시각/순서] |
| 구현 | 읽기·쓰기 | 코드·설정·정본 | 없음 | [시각/순서] |
| 테스트 | 읽기·실행 | 기본 없음 | 승인 시 TEST_HANDOFF | [시각/순서] |

### 요구사항 진행 현황

| ID·버전 | 필수/선택·우선순위 | 진행 상태 | 의존성/차단 | H-ID | 구현 커밋 | T-ID·판정 | 다음 행동 |
|---|---|---|---|---|---|---|---|
| [R-ID v#] | 필수/선택·P0/P1/P2 | 미확정; 확정 / 구현 가능; 구현 중; 구현 완료 / 미검증; 검증 완료; 오류 / 차단됨 | [ID/이유] | [H-ID] | [SHA/없음] | [T-ID·판정] | [한 행동] |

### 패킷·평가·제출 요약

- 마지막 반영 H-ID / T-ID:
- 반영 대기 패킷과 대상 STATUS 개정:
- 평가 추적 완료/미완료:
- 최종 검증 시작 조건·예약 시각:
- 실제 제출 확인 근거:

중요한 단계 전환·중단·복원 때 갱신한다. 문서별 경로가 다르면 위 매핑을 정본으로 사용한다.

## 가상 작성 예

- 정본 STATUS 경로: 프로젝트 안 `work-notes/STATUS.md`
- 상태 개정: EX-S-002, 가상 순서 2(실제 시각 미확인)
- 참고 폴더·START 접근: 미확인, 이 예시에서는 실제 경로 확인 안 함
- 다른 기록: 같은 폴더의 REQUIREMENTS.md, DECISIONS.md, VERIFICATION.md, MVP_REPORT.md
- 현재 목표: EX-R1~EX-R4 정의
- 완료: 가상 답변을 요구사항으로 변환
- 진행: 검증 설계
- 막힘: 없음
- 다음 한 행동: 완료 상태 역전이의 기대값 확인
- 실행: 없음, 문서 흐름 예시
