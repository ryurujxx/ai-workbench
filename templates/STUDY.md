# STUDY

실제 프로젝트 내부에 두는 학습 기록 양식이다. 사용자가 구현과 문제 해결을 자신의 말로 설명하도록 돕는다. 구현 담당이 단일 작성자로 관리하고, 중요한 결정·오류·검증이 생길 때만 짧게 갱신한다. 기획 담당은 H 패킷으로 판단 근거와 학습 요약을, 테스트 담당은 T 패킷으로 실제 검증 결과와 학습 포인트를 전달하며 이 파일을 직접 수정하지 않는다.

실행하지 않은 실험, 발생하지 않은 오류, 비교하지 않은 대안이나 Git 커밋을 만들지 않는다. 모든 주장은 요구사항 ID·코드·실제 SHA 또는 대상 파일 상태·확인 시점·로그·테스트 결과 중 실제 근거를 가리킨다. 중요한 내용을 누적하되 기록 때문에 구현·검증을 지연시키지 않는다.

## 먼저 이해할 업무 흐름

- 만드는 서비스·이용자·업무 목적: [제시문/브리핑 근거]
- 핵심 흐름: [입력 → 업무 판단/처리 → 결과]
- 핵심 선택·이유·대안: [실제 결정/H 근거]
- 대표 실제 장애: [증상 → 확인 원인/가설 → 해결·재검증 / 기록할 중요 오류 없음]
- 독립 검증과 한계: [T 버전·대상·범위·미검증]

첫 화면은 3~5분 복습을 목표로 간결하게 유지한다. 영어 업무/기술명 첫 등장은 한국어 뜻을 병기한다. 모든 함수·라인·사소한 이벤트를 학습 카드로 늘리지 않는다. 실제 실패·원문 로그·재현 명령·실측·필수 증거는 아래 상세 영역 또는 원본 참조에 보존하며 삭제·조작하지 않는다.

## 현재 학습 우선순위

실제 작업에서 확인된 주요 기획 결정·기술 선택·알고리즘·중요 오류·검증 결과 중 사용자가 먼저 이해해야 할 내용만 최대 3개로 유지한다. 이미 학습한 내용과 아직 확인되지 않은 사항을 구분하고, 실제 근거가 없는 항목은 추가하지 않는다.

| 우선순위 | 먼저 이해할 내용 | 구분 | 실제 근거 |
|---|---|---|---|
| 1 | [기획 결정·기술 선택·알고리즘·오류·검증 결과] | 학습 필요/학습함/미확인 | [요구사항·H-ID·코드·SHA·로그·T-ID] |

학습이 끝났거나 우선순위가 바뀌면 실제 진행 상태에 맞게 교체한다. `학습함`은 사용자가 직접 설명하거나 이해 확인에 성공한 경우에만 쓰고, 근거는 있으나 결과가 확정되지 않은 내용은 `미확인`으로 표시한다.

### 1. 기획과 요구사항 의사결정

- 해결하려는 문제와 관련 요구사항:
- 업무자에게 확인한 사실:
- 사용자가 승인한 정책·가정:
- 비교한 주요 대안:
- 최종 선택과 구체적 이유:
- 실제 계산·실험 근거 또는 미검증 사항:
- 사용자가 이해해야 할 핵심 개념:

필요한 데이터 계약·Hard/Soft·목표는 Q-ID/H와 연결한다. 실제 사용자 승인·반려·보류와 이유·요구사항 영향만 남기고 반려나 승인 이유를 만들어내지 않는다.

H 패킷의 사실·승인·비교 근거를 요약한다. 구현 담당이 원문 근거를 확인해 반영하며, 기획 담당은 이 파일을 직접 수정하지 않는다.

비교하지 않았다면 “의미 있는 대안 비교 없음”과 이유를 쓴다. 미실험 성능을 검증 결과처럼 쓰지 않는다.

### 4. 테스트·운영·실행 환경

| 검증 대상·목적 | 환경·격리·소유권 | 명령·절차 | 기대값 | 실제값 | 판정·증거 |
|---|---|---|---|---|---|
| [정상/경계/예외/Browser/Docker] | [개발/격리 테스트/실제 제출 환경, 서버·포트·프로세스·데이터 분리와 한계] | [실제 절차] | [관찰값] | [실제 결과/미실행] | 통과/실패/미검증·[T-ID/근거] |

실행할 수 없었던 테스트는 이유와 사용자가 확인할 절차를 쓴다. 격리 환경 성공과 실제 제출 환경 성공을 구분하고, 포트만 분리됐으나 소스·데이터가 공유되는 경우 완전 격리로 기록하지 않는다.

데이터 검증은 표본/전체 범위, 검산은 기대값 출처·구현과 다른 계산 경로·불변조건, 성능은 입력 규모·환경·측정 방법·시간/메모리·목적함수를 해당할 때만 기록한다. 미실행은 미검증으로 남긴다.
