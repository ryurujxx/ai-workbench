# AI 개발 워크벤치

요구사항 탐색, 사용자 승인, 구현, 독립 검증, 학습 기록을 세 개의 Codex CLI 세션으로 이어 가는 범용 워크벤치다. 전체 기획이 끝날 때까지 기다리지 않고 **승인된 독립 기능은 바로 구현하고, 구현 완료 기능은 바로 검증**한다.

대용량 데이터나 최적화가 필요한 과제에는 표본·전체 검증 구분, 데이터 계약, 제약·알고리즘 트레이드오프, 독립 검산과 성능 측정을 기존 H/T·STATUS·STUDY에 연결한다. 세부 절차는 필요한 경우에만 적용하며 작은 입력 → 처리 → 결과 흐름을 먼저 실행한다.

## 누가 무엇을 하는가

| 참여자 | 역할 |
|---|---|
| 사용자 | `templates/qa.md`의 질문을 업무자에게 전달하고 실제 답변 원문을 기록한다. 중요한 선택을 승인하고 H/T 패킷을 전달하며 `STUDY.md`로 학습한다. |
| 기획 담당 | 자료와 도메인을 탐색하고 실제 과제의 `templates/qa.md`에 질문을 관리하며 승인된 요구사항의 H 패킷을 만든다. 그 외 코드·기록은 수정하지 않는다. |
| 구현 담당 | 승인된 H 패킷만 구현한다. 코드·설정·`STATUS.md`·`STUDY.md`의 단일 작성자이며 자체 검증과 T 요청을 수행한다. |
| 테스트 담당 | `구현 완료 / 미검증` 기능을 독립적으로 검증하고 T 패킷을 반환한다. 코드·설정·`STATUS.md`·`STUDY.md`는 수정하지 않는다. |

세 세션의 대화는 자동으로 공유되지 않는다. 기본 인계 방법은 사용자가 H/T 패킷을 복사해 전달하는 것이다. 안전한 공유 파일이 허용돼도 같은 파일을 여러 세션이 수정하지 않는다.

## 최초 실행부터 제출까지

사용자는 이 워크벤치를 최상위 작업공간의 `ai-workbench/`에 미리 준비한 뒤 같은 Codex 세션에서 `ai-workbench/START.md`를 연다. 워크벤치 내부 절차는 이미 준비된 참고 문서를 읽는 시점부터 시작한다.

1. **터미널 1 — 기획 시작:** [START.md의 STEP 01](START.md#step-01--기획-담당-최초-시작)을 복사한다. 기획 담당은 `ai-workbench/`의 참고 규칙과 실제 과제 README·제공 자료를 구분해 읽고 초기 분석·1차 질문·독립 구현 후보를 제시한다. 이 단계에서는 구현하거나 `STATUS.md`/`STUDY.md`를 만들지 않는다.
2. **질문과 승인:** 기획 담당은 실제 과제 최상위 작업공간의 `templates/qa.md`에 Q-ID가 있는 질문을 누적한다. 사용자는 질문을 업무자에게 전달하고 답변 원문을 해당 Q-ID 아래 기록한다. 기획 담당은 파일 전체를 다시 읽어 확인·충돌·미확정 조건과 필요한 후속 질문을 정리한다.
3. **터미널 2 — 구현 시작:** 첫 번째 승인된 H 패킷을 받은 뒤에만 같은 프로젝트 폴더에서 두 번째 Codex CLI 세션을 연다. 구현 담당은 기존 `STATUS.md`와 `STUDY.md`를 복원하거나 없으면 만들고 구현한다. 기획 담당은 동시에 후속 분석과 H 패킷 작성을 계속한다.
4. **터미널 3 — 테스트 시작:** 구현 담당이 특정 요구사항을 `구현 완료 / 미검증`으로 기록하고, 검증 가능한 실행 상태와 T 요청을 제시한 뒤에만 세 번째 Codex CLI 세션을 연다. `구현 중`이거나 파일만 생성된 상태에서는 시작하지 않는다.
5. **병렬 진행:** 기획은 다음 H를 만들고, 구현은 승인 기능과 수정 사항을 처리하며, 테스트는 완료 기능을 검증한다. 사용자는 업무자 소통·승인·H/T 전달·학습을 맡는다. 구현 담당의 자체 검증은 독립 테스트 시작 여부와 관계없이 계속한다.
6. **최종 검증과 제출:** 남은 시간을 확인하고 실제 제출 환경에서 통합 검증한다. 격리 환경의 성공과 제출 환경의 성공을 구분하며, 허용된 제출 또는 Git Push의 실제 완료 여부를 확인한다.

START의 STEP 번호는 상황별 프롬프트를 찾기 위한 구분이다. 모든 질문을 순서대로 끝낼 필요는 없으며, 첫 승인된 독립 기능은 즉시 H로 구현 담당에게 전달하고 기획 담당은 남은 질문을 계속한다.

`qa.md`에는 1차→답변→필요한 2차 질문을 기존 Q-ID와 연결해 누적하며 원문을 덮어쓰지 않는다. 터미널에는 전체 질문·답변 대신 신규 질문 수, 핵심 쟁점, 즉시 승인 가능한 기능과 다음 행동만 출력한다.

Browser UI는 환경이 허용할 때만 AI가 직접 조작한다. 지원되지 않으면 AI가 포트·경로·확인 항목을 짧게 안내하고 사용자가 미리보기를 조작해 결과를 돌려준다. HTTP 응답 성공만으로 화면 검증 완료로 보지 않는다.

## 무엇을 어디로 전달하는가

- 기획 담당이 `qa.md`에 기록한 질문 → **사용자가 업무자에게 전달**
- 업무자 답변 원문 → **사용자가 해당 Q-ID의 답변 영역에 기록한 뒤 STEP 03 실행**
- 사용자가 승인한 요구사항의 H 패킷 → **터미널 2의 구현 담당에게 전달**
- 구현 담당의 T 요청 → **터미널 3의 테스트 담당에게 전달**
- 테스트 담당의 T 패킷 → **터미널 2의 구현 담당에게 전달**
- 구현 담당의 `STUDY.md` 요약과 이해 확인 질문 → **사용자가 읽고 자신의 말로 답변**

## 학습과 중단 후 재개

`STUDY.md`는 승인된 주요 결정, 기술·알고리즘 선택, 실제 오류 해결, 검증 결과가 생겼을 때 읽는다. 사용자는 기획 결정 직후에도 기획 담당에게 30초 설명과 이해 확인 질문을 요청할 수 있고, 구현 담당은 H의 근거를 STUDY에 통합한다. 학습 우선순위는 최대 3개이며, 답하기 전에는 `학습함`으로 표시하지 않는다. AI 또는 보조 자료 사용이 금지된 단계에서는 학습 지원을 중단한다.

오류나 세션 중단 뒤에는 새로 추측하지 않는다. 구현 담당이 관리하는 `STATUS.md`의 요구사항 버전과 상태, 마지막 정상 실행, 서버·프로세스 소유권, 재시작 방법, 차단 문제, 반영 대기 H/T, 다음 한 작업을 실제 파일·Git·프로세스와 대조해 재개한다. 역할별 재개 프롬프트는 [START.md](START.md)에 있다.

플랫폼·IDE·AI 서버·감독 연결 자체의 장애는 사용자가 AI와 관계없이 공식 문의·문제 신고 절차를 우선한다. AI가 플랫폼 관리 설정이나 프로세스를 바꾸지 않는다.

제출 확정 전 AI 담당은 실행·저장·필수 기능·제출 대상을 검증하고 STATUS/STUDY를 최종 갱신한다. 사용자가 제출 미리보기를 검토하고 최종 확정하면 개발 IDE와 AI의 코드·기록·검증 작업은 끝난다. 이후 AI 사용 금지 후속 문제는 사용자가 직접 답하고 전체 완료 표시를 확인한다.

## 문서 안내

사용자는 먼저 이 문서와 [START.md](START.md)만 보면 된다. AI 담당은 프롬프트의 지시에 따라 필요한 문서를 읽는다.

| 파일 | 용도 |
|---|---|
| [START.md](START.md) | 사용자가 상황별로 바로 복사하는 프롬프트 |
| [AGENTS.md](AGENTS.md) | AI의 역할·권한·승인·보안·인계 규칙 |
| [WORKFLOW.md](WORKFLOW.md) | 탐색부터 제출까지의 AI 실행 절차와 환경 격리 계약 |
| [templates/STUDY.md](templates/STUDY.md) | 실제 프로젝트의 학습 기록 양식 |
| [references/SOURCES.md](references/SOURCES.md) | 공개 참고 자료의 출처·라이선스 확인 범위 |

실제 비공개 자료·데이터·로그·화면·결과물은 이 공개 저장소에 포함하거나 허용되지 않은 외부 서비스로 보내지 않는다. 공개 자료 Clone 허용은 프로젝트 결과물의 외부 반출 허용을 뜻하지 않는다. 일반 개발 환경에서 사용자가 승인한 작업 브랜치 Push·PR은 해당 환경 정책에 따라 사용할 수 있다.

`ai-workbench/`가 작업공간 안에 있다는 이유만으로 자동 삭제·은폐하거나 제출 구조를 바꾸지 않는다. 실제 과제의 제출 범위와 명시적 파일 조건을 먼저 따른다.

실제 업무자 질문·답변은 공개 `ai-workbench/templates/`가 아니라 실제 과제 최상위 작업공간의 `templates/qa.md`에 둔다. 비공개 Q&A를 공개 저장소에 Commit·Push하지 않는다.
