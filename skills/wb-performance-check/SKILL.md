# 계산 성능·품질 비교

## 사용 범위와 입력

- 사용: 큰 입력에서 계산이 과도하거나 개선안의 시간·메모리·품질 교환을 실제로 판단해야 할 때.
- 제외: 작은 기능의 일반 검증, 측정 전 전면 재작성, 마감 직전의 비용 큰 벤치마크·설치.
- 역할: 기획은 비교 기준·허용 품질의 H 승인 제안, 구현은 승인 코드의 측정·개선, 테스트는 완료 대상의 T 측정·제약 검증. 기획은 벤치마크 파일을 작성하지 않는다.
- 입력: 기준 구현/후보 버전·명령, 입력 식별·규모·선정 방법, 승인 제약·목적함수·품질 기준, 실행 환경·자원·소유권, 종료 시각·제출 여유·중단 방법.

## 수행

1. [WORKFLOW의 성능 절차](../../WORKFLOW.md#상황별-선택-데이터-처리계산-성능)를 적용한다. 작은 정답과 제약 검사를 통과한 기준 구현을 보존한다. 작은→중간→허용되는 전체 규모 순으로 정하고 각 실행의 자원·시간 예산을 실제 남은 시간에 맞춘다.
2. 이미 있는 타이머·프로세스 도구로 입력 읽기/파싱·조인·계산·출력 중 병목을 구분한다. 전체 경과 시간과 일부 함수 시간은 분리한다. 메모리는 측정 도구·단위·최고값/현재값·대상 프로세스/자식 포함 여부를 밝힌다. 자료구조 크기 추정치를 전체 메모리 실측으로 쓰지 않는다.
3. 입력·환경·버전·파라미터·시드, 캐시·동시 부하·측정 구간을 맞춰 비교한다. 반복 측정이 필요하면 변동성과 비용을 보고 최소한으로 수행하고 횟수·대표값 산출 방법을 남긴다. 다른 조건의 수치는 참고로만 표시한다.
4. 측정된 병목에만 개선을 제안한다. 스트리밍·인덱스·캐시 등이 실제 중복/메모리를 줄이는지 확인하고 의미·데이터 최신성·제약을 바꾸지 않는지 검사한다. 시간과 메모리가 서로 증가할 수 있으므로 승인 품질·목적값·위반 건수도 함께 비교한다. 빠른 잘못된 결과를 개선으로 선택하지 않는다.
5. 완료·시간 초과·자원 초과·중단과 중간 결과를 구분한다. 시간 초과 후보를 빠른 후보처럼 비교하거나 미측정 개선율을 쓰지 않는다. 개선이 실패하거나 제출 여유가 부족하면 자기 실행만 안전하게 중단하고 보존한 검증 기준 구현으로 돌아간다. 그 기준의 전체 규모 성공 여부도 따로 밝힌다.

## 산출물·권한·복귀

조건·입력 규모 → 기준/후보의 제약 위반·목적값·시간·메모리 → 재현성·위험·남은 시간 → 채택/보류와 미검증을 짧게 반환한다. 기획은 H 기준, 테스트는 T 결과, 구현은 STUDY의 기술·검증 영역과 STATUS의 실행/복구 상태에 연결한다. 정확성·정책·중요 알고리즘 변경은 사용자 승인을 유지한다.

[AGENTS](../../AGENTS.md)의 격리·서버 소유권을 지킨다. 원본 데이터·다른 담당자의 계산을 종료하거나 공유 서버를 부하 시험하지 않는다. 필요한 계측 파일은 역할에 허용된 실제 과제 위치에만 두며, 공개 워크벤치에 실험 데이터를 저장하지 않는다.

측정 도구가 없으면 새 설치 없이 기존 Codex·프로젝트 도구로 가능한 경과 시간과 작은/중간 입력 검사만 수행한다. 메모리·전체 실행 등 못 한 항목은 미검증으로 남기고 필수 기능·제출 흐름으로 복귀한다.
