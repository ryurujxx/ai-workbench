# 데이터 품질·CSV 진단

## 사용 범위와 입력

- 사용: 여러 CSV의 스키마가 불명확하거나 결측·중복·조인 증폭이 결과를 바꾸고, 전체 읽기 비용을 통제해야 할 때.
- 제외: 헤더 확인만으로 충분한 작업, 승인된 데이터 정책을 바꾸려는 요청, 전체 통계가 필요 없는 CRUD.
- 역할: 기획은 읽기 전용 조사와 Q/H 제안, 구현은 승인 H의 처리·자체 검증, 테스트는 완료 대상의 T 검증. 역할별 쓰기 권한은 늘지 않는다.
- 입력: 실제 과제 지시, 파일 위치·크기, 필요한 컬럼·결과, Q-ID/H의 정책·미확정 의미, 읽기 비용·남은 시간. 민감 원문 대신 최소 집계를 사용한다.

## 수행

1. [WORKFLOW의 데이터 절차](../../WORKFLOW.md#상황별-선택-데이터-탐색과-계약)를 기준으로 이번 결과를 바꾸는 검사만 고른다. 파일별 헤더와 한정한 표본에서 구분자·따옴표·인코딩·컬럼 수를 확인한다. 잘못된 문자를 무시하거나 파싱 실패 행을 조용히 건너뛰지 않는다. 파서의 논리 행 수와 파일 줄 수를 구분한다.
2. ID의 앞자리 0, 숫자처럼 보이는 문자열, 빈 값과 0, 날짜 해석·시간대·소수점 형식을 구분한다. 표본의 자료형 추론을 계약으로 확정하지 않고, 변환 실패 건수·최소 사례를 별도로 센다. 필수 여부·결측·중복 처리가 미정이면 근거와 Q-ID 후보를 반환한다.
3. 전체 검사가 필요하면 읽을 컬럼·파일·검사 범위를 먼저 정한다. 기존 파서의 반복 읽기/청크 처리를 활용할 수 있지만 청크별 중복 검사만으로 파일 전체의 키 유일성을 입증하지 않는다. 전체 키 집합도 메모리를 사용하므로 기존 로컬 저장소·정렬 등 가능한 방법과 비용을 비교하고, 자원이 부족하면 유일성은 미검증으로 남긴다.
4. 조인별 예상 관계(1:1/1:N/N:M)와 빈 키 의미를 확인한다. 결합 전후 행·고유 대상·누락 키·총량을 비교하고 양쪽 키 중복으로 생긴 증폭을 찾는다. 무조건 중복 제거하거나 키 없는 행을 삭제하지 않는다. 합계 보존은 해당 업무 의미가 성립할 때만 적용한다.
5. 원본 식별·표본 선정/전체 범위·실제 방법·결과·미검증을 반환한다. 필요한 처리만 승인 계약과 연결하고, 출력 파일이 있으면 다시 읽어 행 수·스키마·핵심 집계를 확인한다.

## 산출물·권한·복귀

파일/컬럼 → 관찰 범위 → 품질 문제·건수 → 해석 질문/승인 정책 → 검증 결과를 짧게 전달한다. 기획은 `qa.md`의 질문·내부 분석 및 H, 테스트는 T, 구현은 H/T 근거를 STUDY에 통합한다. 별도 데이터 계약 문서는 기본으로 만들지 않는다.

[AGENTS](../../AGENTS.md)의 원본 보존·외부 반출·파일 소유권을 따른다. 실행 스크립트·변환 파일 작성은 구현 담당 또는 허용된 격리 테스트 범위에 한정하며, 실제 과제 자료를 이 공개 Skill 폴더에 저장하지 않는다. 표본 정상은 전체 정상의 증거가 아니다.

사용이 어렵거나 비용이 크면 새 패키지를 설치하지 않고 기존 Codex·파서로 헤더/작은 사례와 필수 검사만 진행한다. 전체 미확인 범위와 이유를 H/T에 남기고 승인된 독립 기능은 계속한다.
