# 독립 검산 설계·실행

## 사용 범위와 입력

- 사용: 테스트는 통과했으나 합계·개별 배정·정책 준수의 정답 근거가 약하거나 핵심 수치의 오류 위험이 클 때.
- 제외: 단순 빌드 재실행, UI 모양만 확인하는 일, 미승인 업무 규칙을 정답으로 강제하는 일.
- 역할: 기획은 H의 검산 기준 제안, 구현은 자체 검산, 테스트는 T 요청을 받은 완료 대상의 독립 검증. 구현 담당의 실행은 독립 테스트 완료로 기록하지 않는다.
- 입력: 승인 Q/H·요구 버전, 원본 입력과 결과·대상 식별자, 계산 정의·단위·허용 오차, 기존 테스트가 검증하는 것과 사용 함수, 안전한 실행 범위.

## 수행

1. [WORKFLOW의 독립 검산](../../WORKFLOW.md#독립-검산과-결과-타당성)에서 위험이 큰 주장 하나부터 고른다. 기대값은 요구·원본·손계산에서 만들고 구현 출력에서 역으로 만들지 않는다. 기대값 출처와 계산에 남은 가정을 먼저 밝힌다.
2. 작은 입력을 직접 계산하거나, 구현과 다른 계산 경로(SQL/원본 재집계/별도 단순 계산 등)를 정한다. 핵심 구현 함수를 가져와 호출하거나 동일 전처리 가정을 반복하면 독립성 한계로 표시한다. 코드를 다른 언어로 옮겼다는 사실만으로 독립성을 주장하지 않는다.
3. 합계와 별도로 승인된 개별 제약 위반을 센다. 입력 대상이 출력·제외·미처리에 어떻게 대응하는지 확인한다. 위반 건수와 최소 재현 대상을 남긴다. 유효한 배정이 여럿이면 승인된 동률 규칙이 없는 한 결과 배열의 완전 일치보다 제약과 목적값을 검증한다.
4. 관련 제한값 바로 아래/같음/위, 빈 입력·중복·잘못된 값·불가능 조건을 고른다. 수치 오차는 업무 기준·정밀도에서 정하고 통과시키기 위해 임의로 넓히지 않는다. 행 순서 변경 같은 변형 검사는 업무상 결과 불변이 성립할 때만 사용한다.
5. 기대/실제·통과/실패/미검증·범위·명령과 근거를 반환한다. 실제 실패는 구현 담당에게 전달하고 수정된 대상에서 동일 사례·관련 회귀를 재검증한다. 검증 중 대상이 바뀌면 기존 통과를 현재 버전으로 옮기지 않는다.

## 산출물·권한·복귀

검증할 주장 → 기대값 근거 → 구현과 다른 경로/독립성 한계 → 실제 결과·위반 → 미검증을 H/T의 기존 필드에 담는다. 구현 담당만 STUDY에 반영한다. 테스트 담당은 [AGENTS](../../AGENTS.md)의 원본·서버·데이터 보호와 격리 조건을 지킨다. 오류를 만들 목적으로 원본 코드·프로세스를 변조하지 않는다.

독립 계산 환경이 없으면 새 도구 설치 대신 읽기 전용 대조·작은 손계산 또는 사용자 확인 절차로 돌아간다. 가능한 검증만 수행하고 독립 검산이 안 된 주장과 이유는 미검증으로 남긴다. API 성공을 Browser 검증으로 바꾸지 않는다.
